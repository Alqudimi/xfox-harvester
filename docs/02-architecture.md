# 2) المعمارية

## نظرة عامة

النظام مقسّم إلى أربع طبقات ذات اتجاه واحد للاعتماد — كل طبقة تعرف ما تحتها ولا شيء يعرف ما فوقها:

```
┌────────────────────────────────────────────────────────────┐
│  الواجهة (web/)   React + Vite + Tailwind — عربية RTL/إنجليزية │
└──────────────────────────┬─────────────────────────────────┘
                           │ REST + SSE (كوكي JWT)
┌──────────────────────────▼─────────────────────────────────┐
│  طبقة API (xfox/api/)   FastAPI — مصادقة، RBAC، تحقق Pydantic │
└──────────────────────────┬─────────────────────────────────┘
                           │
┌──────────────────────────▼─────────────────────────────────┐
│  المحرك (xfox/engine/)  المنسّق + المجمّع + المخاطر + المشغّل     │
│  ┌──────────────────────────────────────────────────────┐  │
│  │ محوّل X-CrawlFox (xcrawlfox.py + workspaces.py)        │  │
│  │   عمليات فرعية: x-crawlfox x all --config … --proxy …  │  │
│  └──────────────────────────────────────────────────────┘  │
└──────────────────────────┬─────────────────────────────────┘
                           │
┌──────────────────────────▼─────────────────────────────────┐
│  البيانات (xfox/db/)    SQLAlchemy 2 async + PostgreSQL JSONB │
└────────────────────────────────────────────────────────────┘
          ▲
┌─────────┴──────────────────────────────────────────────────┐
│  النطاق (xfox/domain/)  تعدادات + سياسات نقية (بدون أي I/O)    │
└────────────────────────────────────────────────────────────┘
```

**قاعدة ذهبية:** كل منطق القرار (التباعد، التراجع، الصحة، المخاطر) يعيش في `domain/policies.py` كدوال نقية قابلة للاختبار بالميلي ثانية — المحرك يُغذّيها بالحالة ويطبّق مخرجاتها فقط.

## تدفق تشغيل واحد (Run Lifecycle)

```
جدولة (كل 5 ثوانٍ)                     تنفيذ
────────────────────                  ──────────────────────────────────────────
job.next_run_at <= الآن؟ ──نعم──► إنشاء صف Run بحالة queued
                                      │
                                   دورة الإطلاق:
                                      ├─ هل المحرك متوقف (خطر أحمر)؟ → انتظار
                                      ├─ هل نافذة النشاط مغلقة؟ → انتظار
                                      ├─ هل الفجوة العامة لم تنقضِ؟ → انتظار
                                      └─ اختيار حساب من المجمّع (LRU + صحة)
                                             │ لا حساب متاح ← Run=skipped
                                             ▼
                                      Run=running + حدث بدء
                                             ▼
                                   توليد crawl_config.json في مساحة عمل الحساب
                                             ▼
                                   عملية فرعية: x-crawlfox x all …
                                     • cwd = مساحة الحساب (كوكيز + حالة)
                                     • بث السجل سطراً سطراً → SSE + ملف
                                     • مهلة قصوى → قتل شجرة العمليات
                                             ▼
                                   تصنيف السجل → OutcomeKind
                                             ▼
                                   قراءة JSONL → استيعاب (upsert) → PostgreSQL
                                             ▼
                                   تحديث: صحة الحساب + حالة المهمة +
                                   الجدولة القادمة (أو تراجع أسي عند الفشل) +
                                   أحداث + إعادة تقييم المخاطر
```

## مكوّنات المحرك

| الملف | المسؤولية |
| --- | --- |
| `orchestrator.py` | حلقة الإشراف: تقييم المخاطر، تحويل المهام المستحقة إلى طابور، إطلاق التشغيلات وفق كل البوابات (تزامن، فجوة عامة، ساعات نشاط) |
| `accounts.py` | اختيار الحساب الآمن: الأهلية من `policies` ثم ترجيح LRU + الصحة |
| `runner.py` | تنفيذ تشغيل واحد من أوله لآخره (أعلاه) |
| `xcrawlfox.py` | بناء أوامر CLI وتنفيذها وضبط المهلة والقتل الشجري — **الوحدة الوحيدة التي تلمس الأداة** |
| `workspaces.py` | مساحة عمل معزولة لكل حساب (`.x-crawlfox/`) + التحقق من الكوكيز وتثبيتها وقراءة المخرجات |
| `outcomes.py` | ترجمة عبارات سجل الأداة (مأخوذة حرفياً من شيفرتها) إلى `OutcomeKind` |
| `risk.py` | غلاف حالة لمقياس المخاطر العام |
| `ingest.py` | تحويل `CrawledItem` إلى نموذج البيانات الداخلي |
| `events.py` | ناقل أحداث في الذاكرة (SSE) + الكتابة الدائمة في جدول `events` |

## لماذا `x all` لكل شيء؟

أمر `x all` هو الأمر الوحيد في الأداة الذي يشغّل **كل** الوحدات (بحث، تايم لاين، أخبار، مراقبة) **مع المصادقة** وفي جلسة متصفح واحدة. توليد ملف إعداد يحتوي القسم المطلوب فقط يعطينا: مساراً موحداً للاختبار، سلوكاً بشرياً طبيعياً (جلسة واحدة تتجول)، وعزلاً كاملاً بين المهام.

## قرارات تصميمية مهمة

- **PostgreSQL + JSONB**: الإحصاءات والوسائط والخام في JSONB (مرونة الاستقصاء) مع فهارس عادية للحقول المفلترة و trigram للبحث النصي العربي/الإنجليزي الموحد.
- **استيعاب idempotent**: المفتاح الأساسي للمنشور هو معرّف X نفسه — إعادة حصد نفس المنشور لا تُنشئ تكراراً، وعدّاد «الجديد» دقيق دائماً.
- **SSE بدل WebSocket**: تحديث باتجاه واحد يكفي للوحة، ويعمل عبر أي بروكسي بدون إعداد إضافي.
- **صحة الحساب مُشتقة من التاريخ لا تُخزَّن**: سلسلة إخفاقات المصادقة تُحسب من سجل التشغيلات — لا حالة منفصلة قد تفسد.
- **كل شيء في أحداث**: كل قرار يتخذه المحرك (تهدئة، تراجع، إبطال حساب، تغيير خطر) يُسجَّل في جدول الأحداث ويُبَث حياً — لا صناديق سوداء.
- **واجهة مبنية مسبقاً**: `web/dist` تُخدَم من FastAPI مباشرة — عملية واحدة، صفر CORS في الإنتاج.
